# Sprint 9 — Trading UI (Angular)

Angular 21, standalone components + signals throughout, no `NgModule`
anywhere. Built by Person 1 (SEC4-633, SEC4-634) as the foundation four
other people branch from — see `docs/prompts/` for the full team split.

## Build

```bash
node -v   # needs 20.19.x, 22.12.x, or 24.0.0+ — Angular 21 refuses below that
npm ci
npm run build
npm test
```

`npm test` runs `ng test`, which on Angular 21 is Vitest under the hood
(`@angular/build:unit-test`), not Karma/Jasmine — specs are still plain
`describe`/`it` `*.spec.ts` files beside the code they cover, nothing
about how you write a spec changes.

## Run against the real backends

`sprint-06-trade-api` (port `8085`) and `sprint-08-auth-service` (port
`3000`) have no CORS configuration (checked directly in both source
trees). Rather than touch either service, `npm start` proxies same-origin
`/auth-api/*` and `/trade-api/*` requests to them (`proxy.conf.json`,
wired as the default `serve` config in `angular.json`) — the browser
never makes a cross-origin request in dev.

```bash
./run-local.sh start   # from the repo root — brings up Postgres, trade-api, auth-service
npm start               # from here — serves this app on :4200, proxied
```

## The generated clients (SEC4-634)

Generator: `@openapitools/openapi-generator-cli`, pinned to the **exact**
version `2.41.0` in `package.json` (no `^`); the underlying generator jar
is pinned to `7.25.0` in `openapitools.json`. Target: `typescript-angular`
(HttpClient-based services returning `Observable` — observables stop at
`HttpClient`, later code converts at the edge with `toSignal`/`rxResource`).

```bash
npm run generate:clients   # regenerate both, after any contracts/*.yaml change
```

`--skip-validate-spec` is set for a checked reason, not reflexively: the
generator's 3.1 validator requires `info.license.identifier`, which the
OpenAPI spec makes optional and neither `contracts/auth-api.yaml` nor
`contracts/trade-api.yaml` carries. The contracts are correct and not
ours to edit.

Both trees are **committed**, not git-ignored (`.gitignore` says so in a
comment rather than an ignore rule). Regenerate into these same paths and
commit the diff in the same commit as the code that adapts to it. Never
hand-edit a file inside `generated/` — an awkward shape gets wrapped in a
service of your own outside the tree instead.

`app.config.ts` is the "something outside the generated tree imports the
clients": it calls both trees' `provideApi()` (aliased on import, since
both export a function of that same name) with base URLs from
`core/config/environment.ts`.

## ZardUI (compulsory — see `docs/prompts/README.md`)

Set up via `npx zard-cli@latest init --yes`, base colour `neutral`, style
`css` (CSS-variable theming, matching the design tokens below), icons
`lucide` (kept — see `docs/prompts/README.md`'s icon-set note). Baseline
components installed: `button input card badge table dialog select tabs
checkbox skeleton spinner separator alert` (+ `input-group`, pulled in as
a dependency of `input`). Add more with `npx zard-cli@latest add <name>`,
committed under `src/app/shared/components/`.

**Icon-size scale:** 16px inline with body text, 20px inside a
button/input, 24px standalone — pass explicitly via `ng-icon`'s `size`
input (e.g. `<ng-icon name="lucideCheck" size="16" />`); there's no global
default worth relying on. Consistent stroke width is Lucide's own default
(1.5–2, not mixed) — don't override per-icon.

## Design tokens (`src/styles.css`, `src/index.html`)

Deliberately not the ZardUI/shadcn defaults — see `docs/prompts/
README.md` for the full reasoning:

| Token | Decision | Why |
|---|---|---|
| `--background` | `oklch(0.985 0.002 90)` (light) — an off-white, not `#fff` | avoids the flat "pure white background" look |
| `--primary` | a blue (`oklch(0.5 0.14 250)`) | not purple, not the shadcn default near-black |
| `--success` / `--success-foreground` | added — neither shadcn nor Tailwind ships one | SEC4-640's badges need a colour-blind-safe green, paired with the status word, never colour alone |
| `--radius` | `0.375rem`, down from the `0.625rem` default | avoids the oversized/soft-corner look |
| `--font-sans` | IBM Plex Sans | not Inter, Geist or Space Grotesk |
| `--font-mono` | IBM Plex Mono, via the `.tabular-figures` utility class | tabular numerals for price/quantity columns, so decimals align in the order ticket and blotter |

Fonts are loaded from Google Fonts in `src/index.html` (`preconnect` +
one `<link>`) — self-hosting is a reasonable upgrade later, not required
for this sprint.

## The six shared-foundation pieces

Built so Persons 2/3/4 can branch from this and work **in parallel**
without touching each other's files (full reasoning in `docs/prompts/
README.md`):

1. `core/config/routes.const.ts` — `ROUTE_PATHS`.
2. `core/config/environment.ts` (+ `.production.ts`) — `apiBaseUrls`,
   `allowedOrigins`.
3. `core/auth/token-store.ts` — `TokenStore` (working, in-memory).
4. `core/auth/account-context.ts` — `AccountContext` (decodes `accountId`/
   `roles` off the JWT payload per `contracts/auth-api.yaml`'s normative
   claims table — no signature verification, that's the Trade REST API's
   job on every call).
5. `core/errors/error-message.service.ts` — `ErrorMessageService`
   placeholder; public shape `getMessage(errorCode: string | null,
   httpStatus: number): string` is fixed, Person 3 replaces the body.
6. Placeholder routes/components for `sign-in`, `order-ticket`, `blotter`
   — each a ZardUI `Card`, wired into `app.routes.ts`, lazy-loaded.
